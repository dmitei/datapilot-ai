# Архитектура DataPilot AI и вопросы к собеседованию

## Начни с одного запроса

Для фразы «Покажи динамику доходов по месяцам за 2024» путь выглядит так.

1. `datapilot/__main__.py` принимает текст через aiogram или из аргумента командной строки. Оба входа вызывают `report_for()`.
2. `datapilot/assistant.py` извлекает год и выбирает `monthly_revenue`. Команда выбирает инструмент напрямую, демо ищет ключевые слова, режим LLM читает `tool_calls` из ответа модели.
3. `datapilot/analytics.py` проверяет имя и год. Функция `run_tool()` берёт соединение из пула asyncpg, выполняет фиксированный запрос в транзакции только для чтения и возвращает объект `Report`.
4. `datapilot/charts.py` строит график из тех же строк, которые используются для текстового ответа. Matplotlib рисует в память с backend Agg. Бот отправляет PNG через `BufferedInputFile`, а CLI сохраняет его на диск.

Файл `init.sql` создаёт пустые таблицы. Модуль `import_db.py` читает SQLite в режиме только для чтения или разбирает CSV, проверяет строки и сохраняет их в PostgreSQL в одной транзакции. Успешная загрузка целиком заменяет предыдущий набор. Telegram принимает файлы и запросы только от владельца, указанного в `BOT_OWNER_ID`. Связь один-ко-многим идёт по `company_id`. Ключ `(company_id, month)` обеспечивает одну строку на компанию в месяц. Выручка и расходы измеряются за месяц, кредитный остаток измеряется на конец месяца. Суммирование остатков по месяцам завысило бы годовой портфель, поэтому пятый инструмент берёт декабрьский срез.

## Как используется модель

Приложение отправляет схемы пяти функций с обязательным целочисленным параметром `year`. Ответ принимается только при одном вызове известной функции с ожидаемым годом. Год и границы периода передаются в SQL как параметры, а текст запроса хранится в коде. За выбор отчёта отвечает модель, за доступ к данным и расчёт отвечает сервер. Второй вызов модели не нужен, поскольку текст и график строятся непосредственно из результата запроса.

- [Документация aiogram по отправке файлов](https://docs.aiogram.dev/en/dev-3.x/migration_2_to_3.html#sending-files)

## Вопросы для самопроверки

1. **Чем `async def` отличается от обычной функции?** Вызов создаёт объект корутины. Во время `await` сетевого I/O цикл событий может выполнять другие готовые задачи.
2. **Почему график строится через `asyncio.to_thread`?** Matplotlib работает синхронно. Вынос рендера в поток освобождает цикл событий для обработки других сообщений. Блокировка сериализует вызовы рендера, поскольку Matplotlib использует общее состояние.
3. **Зачем пул соединений?** Он переиспользует соединения PostgreSQL и ограничивает их число. `async with pool.acquire()` возвращает соединение в пул даже при исключении.
4. **Что защищает от SQL-инъекции через ответ LLM?** Код разрешает пять известных имён, проверяет структуру аргументов и передаёт год отдельно от текста SQL. Транзакция только для чтения добавляет ещё один барьер.
5. **Чем tool calling отличается от получения обычного текста?** Модель возвращает структуру с именем функции и аргументами. Python проверяет структуру и решает, выполнять ли инструмент.
6. **Как устроен отчёт топ-5?** `JOIN` связывает показатели с компаниями, `GROUP BY` формирует одну группу на компанию, `SUM` считает годовую выручку, а `ORDER BY ... LIMIT 5` выбирает пять лидеров. ID определяет порядок при равенстве выручки.
7. **Почему деньги хранятся в `bigint`?** Демо хранит целые рубли, поэтому суммы точны. Деление на миллион применяется только при визуализации. Для копеек можно хранить целое число минимальных денежных единиц.
8. **Какие тесты проверяют разные части системы?** Тест маршрутизации подаёт пользовательские фразы, HTTP-имитация проверяет формат tool calls, а интеграционный тест выполняет реальные SQL-запросы и сверяет результаты.

Чтобы подготовиться к рассказу о проекте, прогони один запрос в терминале, найди соответствующую запись в `METRICS` и объясни, какие строки PostgreSQL сначала отбирает и как затем их агрегирует.
